## Published-pair acceptance

Exact published packages, isolated environment, no source substitution:

```bash
uv venv tmp/pypi --python 3.14
uv pip install --python tmp/pypi/bin/python 'okama-mcp==3.1.0'
tmp/pypi/bin/python -I tests/release/published_pair.py \
  --fixtures examples/planner --output tmp/pypi-acceptance
```

Resolved: `okama-mcp 3.1.0`, `okama-planner 0.5.1`, `okama 4.0.1`, `fastmcp 4.1.4`.
Receipt `status: PASS`, `public_tool_count: 52`, `personal_tool_count: 70`, an anonymous
report artifact (`report-efbdd18eb68b43e4a78fab132aea8681.xlsx`), a synthetic database
with its `synthetic.sqlite3.mcp-access.json` policy file, and all three privacy
rejections (`unsigned`, `tampered`, `invalid_request`).

`live_finplan: false` is expected: the fixture plan uses supplied return samples, so the
acceptance performs no market-data download.

## Landing

`deploy/nginx/index.html` and `deploy/nginx/announce-en.png` were deployed to
`/var/www/okama-mcp/public/` after a dated backup of both files. Verified byte-identical:

```bash
curl -s https://mcp.okama.io/ | diff - deploy/nginx/index.html
curl -s https://mcp.okama.io/announce-en.png | cmp - deploy/nginx/announce-en.png
```

The cover was re-rendered at 1200×630 because the standard install grew to 52 tools; the
Russian cover had still been showing the 1.6-era 47.
