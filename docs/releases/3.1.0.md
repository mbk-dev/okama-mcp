# okama-mcp 3.1.0

**Unreleased.** Source changes are prepared for merge; package publication is deferred.

Prepares the compatible Planner integration and introduces an explicit local
personal-data access switch. Requires `okama-planner[reports]>=0.5.0,<0.6.0`.

- 52 public tools include household forecast/comparison and core `finplan_*`.
- Default local client access is anonymous and read-only. With report export:
  60 tools; client maintenance stays in Planner's HTML interface.
- Local stdio `--allow-personal-data` enables full client records and CRUD,
  meetings and bounded history reads through Planner: 68 tools with report export.
  LLMs cannot enable the flag; HTTP cannot expose local client access.
- MCP imports no database driver/ORM and executes no SQL. Planner owns every read,
  write and deletion, including ownership checks and transaction rollback.
- Forecast/report outputs retain the anonymous signed contract and tamper rejection.
- Development CI uses the immutable Planner source pin and installed-wheel acceptance.
  Release gates disable that pin and require published Planner before upload;
  the exact PyPI package is checked after publication without source substitutions.

```bash
uv venv tmp/pypi
uv pip install --python tmp/pypi/bin/python 'okama-mcp==3.1.0'
tmp/pypi/bin/python -I tests/release/published_pair.py \
  --fixtures examples/planner --output tmp/pypi-acceptance
```

Synthetic records only; each run requires a fresh output directory.
