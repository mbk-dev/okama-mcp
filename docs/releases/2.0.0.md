# okama-mcp 2.0.0

## New
- Planner household forecasts and controlled single/per-goal comparisons from MCP.
- Local `client_create`, `client_get`, `client_list`, `client_update`,
  `client_set_tax_residency`, `client_get_tax_residency`, backed by PlannerStore.
- Creation receipts, explicit namesake decisions and stable codes after restart.
- Local `planner_export_report` for saved forecasts, with separately configured branding.
- Distributed `create-client` skill and `install-skill` command.

## Changed
- FastMCP >=4.0.11,<5 replaces the previous >=2.7 floor. Python remains >=3.11.
- Local database/report options exist only on stdio; HTTP has a separate public registry.
- `init-client-db` explicitly initializes a new owner-only empty database.
- Planner `>=0.4.0,<0.5.0` with the `reports` extra is a mandatory runtime dependency.
  Forecast/comparison and Excel dependencies arrive with an ordinary MCP installation.
- okama >=4.0.0 includes the released financial-plan fixes. The MCP time-series
  cash-flow mode remains explicit, preserving its existing default.
- Existing portfolio/finplan contracts are preserved.

## Upgrade
Follow [the Planner installation and upgrade guide](../planner.md). Keep private
records, receipts and presentation settings locally. Planner 0.4.0 and okama
4.0.0 are published on PyPI and resolve as named runtime dependencies.

## Publication
The owner authorized release publication on 2026-10-09 after candidate acceptance.
The tag-driven release publishes to PyPI and the MCP registry. GitHub release
notes and the static landing page are updated as part of this workflow.
Local client storage remains explicitly configured by each installation.

## Validation
Evidence is recorded in `docs/releases/2.0.0-validation.md` after final candidate
verification. Synthetic stdio acceptance is reproducible with
`poetry run python examples/local_planner_client.py`; no real client data is read.
